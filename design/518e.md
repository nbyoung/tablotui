# Design 518e: Actions

Four keys act on the selected task: `r` records a status, `v` reviews the gate under the cursor, `a` reaffirms and `u` authorises. Each plans one commit through tabloio's exported package `github.com/nbyoung/tabloio/action`, shows the plan in a mode that takes the body, and makes the commit on `y`. The design adds one package, `internal/ui/act`, and changes no code of the frame. These choices shape it. The interface decides nothing about roles: the package refuses or warns by the hand that commits, and the interface shows what it says (D1, D2). The selection is the argument, so only `r` has a form (D6). Nothing writes at a `--ref`, and nothing writes about a task whose own files hold an uncommitted edit (D3, D4). Only `y` commits (D5). A person at a keyboard leaves no agent trailer (D7). A quit waits for a commit in flight (D12).

## The model

### The package

`internal/ui/act` imports `internal/ui`, tabloio's `action`, Bubble Tea, `bubbles/key` and the standard library. It imports neither the grid, `internal/source` nor `internal/view`: an action needs the selection, which the frame hands it, and the facts of one task, which it takes from the same `action.Source` the plan reads (D1).

```go
// Package act holds the four actions of the tablotui program: record a
// status, review a gate, reaffirm and authorise. Each is a ui.Command that
// plans one commit through tabloio's action package, shows it in a ui.Mode
// and makes it on confirmation.
package act

// Repo is what the actions need of *action.Repo, which satisfies it.
type Repo interface {
	Record(ctx context.Context, rec action.Recording, o action.Options) (*action.Plan, error)
	Review(ctx context.Context, ids []string, gate string, o action.Options) (*action.Plan, error)
	Reaffirm(ctx context.Context, ids []string, o action.Options) (*action.Plan, error)
	Authorise(ctx context.Context, ids []string, o action.Options) (*action.Plan, error)
	Apply(ctx context.Context, p *action.Plan) (action.Result, error)
}

// Facts is what the record form needs of an action.Source, which satisfies it.
type Facts interface {
	Project(ctx context.Context) (action.Project, error)
	Task(ctx context.Context, id string) (action.Task, error)
}

// Options configures the actions.
type Options struct {
	Repo   Repo   // nil: no action runs, and each key says so
	Facts  Facts  // the facts behind the record form; required with Repo
	Dir    string // the project directory, the one that holds .tableaux
	Ref    string // the --ref in view; when not empty nothing writes
	Viewer string // the email the view is drawn for; "" when the command names none
	// Context ends the plans when the program ends; nil is context.Background.
	Context context.Context
	// Uncommitted lists the paths under dir/.tableaux, relative to dir, that
	// differ from HEAD or that Git does not track; nil is GitUncommitted.
	Uncommitted func(ctx context.Context, dir string) ([]string, error)
	// Poke asks the watcher for a load now; the actions call it after every
	// Apply. nil does nothing.
	Poke func()
}

// Actions is the four commands and the commits they have in flight.
type Actions struct{ /* o Options; ctx; wg sync.WaitGroup; flying atomic.Int32 */ }

// New builds the actions.
func New(o Options) *Actions

// Commands returns the four commands in the order r, v, a, u.
func (a *Actions) Commands() []ui.Command

// Busy reports whether a commit is in flight.
func (a *Actions) Busy() bool

// Wait blocks until no commit is in flight. The command calls it after the
// program ends, so that a quit never cuts a commit in two.
func (a *Actions) Wait()

// GitUncommitted lists the paths under dir/.tableaux, relative to dir and
// sorted, that differ from HEAD or that Git does not track. It runs git twice
// and writes nothing.
func GitUncommitted(ctx context.Context, dir string) ([]string, error)
```

Unexported: `kind` (`record`, `review`, `reaffirm`, `authorise`, whose `String` is the package's command name); `*mode`, the one `ui.Mode`; `*form`, the record form; and two messages, `plannedMsg{to *mode; plan *action.Plan; err error}` and `appliedMsg{to *mode; res action.Result; err error}`. A mode handles a message only when `to` is the mode itself, so the plan of a form the viewer left never reaches the next one.

The bindings: `r` `record a status`, `v` `review the gate`, `a` `reaffirm the status`, `u` `authorise the task`. The help mode lists them under `Commands`.

### From the key to the commit

`Command.Run` receives the selection and returns one command; the frame hands it no `Context` and runs nothing when a mode opens. So the command does every blocking step before the mode opens and answers with exactly one message: a `ui.NoticeMsg`, or a `ui.OpenModeMsg` whose mode already holds its form, its plan or its refusal. The screen stays as it stands meanwhile, as the grid keeps its view during a load.

| Step | Where | Does |
|------|-------|------|
| 1 | The command of `Run` | The checks of [Before a plan](#before-a-plan), in order; then `Facts.Project` and `Facts.Task` for `r`, or the plan function for `v`, `a` and `u` |
| 2 | The mode, stage `form` (`r` alone) | The viewer sets the fields; `enter` moves to `planning` and returns the command that calls `Repo.Record` and answers `plannedMsg` |
| 3 | The mode, stage `confirm` | Shows `Plan.String()`; `y` moves to `applying` and returns the command that calls `Repo.Apply` |
| 4 | The command of `Apply` | Runs under `context.WithoutCancel`, counts itself in the wait group, calls `Poke`, and answers a `tea.BatchMsg` of three: `ui.ReloadMsg{}`, a `ui.NoticeMsg`, and `appliedMsg` |
| 5 | The mode, on `appliedMsg` | Closes on success; else moves to `stopped` and shows why |

Step 4 answers with the reload and the notice themselves because the frame closes a mode on `esc` without telling it: the commit of a mode the viewer left still refreshes the panes and still says `committed …`. A plan error at step 1 opens the mode in `stopped`; at step 2 it returns the mode to `form` with the reason beneath the fields, so the viewer corrects and plans again. The stages `planning` and `applying` ignore every key.

### The four actions

Every plan call passes the zero `action.Options` and one id.

| Key | Needs | Plan | Who may, as the package reads the hand | Form |
|-----|-------|------|----------------------------------------|------|
| `r` | A task that is a leaf | `Record(rec)` | Anyone: `not-contributor` and `model-missing` warn; a reviewed gate the status passes is `unreviewed` unless the hand holds the reviewer, and then the plan carries `Reviewed:` by itself | Gate, state, reason, note |
| `v` | A task and a gate cell | `Review([id], gate)` | The junction's reviewer, else `wrong-hand` | None |
| `a` | A task | `Reaffirm([id])` | Anyone: `not-contributor` warns; `not-leaf` and `no-status` refuse | None |
| `u` | A task | `Authorise([id])` | An authority of the task, the owner for the root, else `wrong-hand`; `off-trunk` off the trunk | None |

The interface checks no role. A role holds per task and junction, while the envelope's `viewer.roles` hold across the project, and the hand that commits is Git's identity, which need not be the person the view is drawn for. One reading, the package's, then decides for the command line and for this interface alike (D1). The interface offers no `propose`, no `--pin`, no second task, no `--message` and no `--body`; tabloio's command line has them (D10).

### Before a plan

The command of step 1 answers the first notice that applies. Only the two marked rows are errors, which the frame prefixes `error: `.

| # | When | Notice |
|---|------|--------|
| 1 | `Options.Repo` is nil | `no action: this build draws fixtures` |
| 2 | `Options.Ref` is not empty | `--ref <ref> shows a commit; nothing writes there` |
| 3 | The selection names no task | `select a task first` |
| 4 | `v`, and the selection names no gate | `move the cursor to the gate you review` |
| 5 | `Uncommitted` fails (error) | The first line of its error: `git <subcommand>: <git's first line>` |
| 6 | `Uncommitted` lists `.tableaux/status/<id>.yaml`, else `.tableaux/tasks/<id>.yaml` | `status/<id>.yaml holds an uncommitted edit; commit or restore it`, or the same for `tasks/<id>.yaml` |
| 7 | `r`: `Facts.Project` or `Facts.Task` fails (error) | The first line of the error |
| 8 | `r`: the task has children | `<id> is a parent; its children hold the status` |

A notice is one line, and the frame cuts it with `…`; the longest fixed text is 64 cells with a four-digit id.

**At a ref, nothing writes** (row 2). A write acts on the checkout's `HEAD`, and a view at `--ref` shows some other commit, or the same one without the working tree; the rule has no exception for `--ref HEAD` (D4).

**An uncommitted edit that the view shows** (row 6). The default view reads the working tree, and the package plans on `HEAD` (A2). An empty commit that says `Reaffirmed:` or `Authorised:` would then confirm the committed file while the viewer reads the edited one, so all four actions refuse while the task's own status file or task file differs from `HEAD`. Any other path that `Uncommitted` lists refuses nothing: the form and the confirmation then carry the line `uncommitted edits under .tableaux; the plan reads HEAD` (D3). `GitUncommitted` runs `git -C <dir> diff --name-only -z --relative HEAD -- .tableaux`, then `git -C <dir> ls-files -z --others --exclude-standard -- .tableaux`, each with `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0` and `LC_ALL=C` added to the environment, and returns the union, sorted. The paths are relative to `dir`, so a project below the repository root compares the same way.

### The record form

The form reads `Project` and `Task` once. `old` is the task's status, or `undefined`, `undefined` when it has no file.

- **Gate.** The choices are the gates of `Project.Gates` whose junction for the task is not `not-applicable`. The default is `old`'s gate; when the cursor stands on a later gate among the choices, that gate. A gate before the status never becomes the default.
- **What the gate decides**, in the package's order. The gate `undefined` fixes the state `undefined`. A gate with no later choice fixes `complete`. A gate whose next choice has a `recursive` junction holds the file to the gate alone: state, reason and note take no input. Otherwise the state is a choice.
- **State.** The choices are `Project.States` without `undefined` and `complete`. The default is `old`'s state when the gate is `old`'s and the state is a choice, else the first choice.
- **Reason.** The choices are `none`, then `Project.Reasons`. The default is `old`'s reason when the gate is `old`'s, else `none`.
- **Note.** One line of text. The default is `old`'s note when the gate is `old`'s, else empty.

When the gate changes, each of the three fields the viewer has not changed takes its default for the new gate; a field the viewer changed keeps its value. `enter` sends every field explicitly, so the plan writes what the form shows: `Recording{ID, Gate}` alone when the gate holds the file; else `State` (the fixed one, or the choice), `Reason` or `NoReason` for `none`, and the trimmed `Note` or `NoNote` when it is empty (A5).

| Key | In the form |
|-----|-------------|
| `down` `tab`, `up` `shift+tab` | The next or the previous field that takes input, round the ends |
| `right`, `left` | On a choice: the next or the previous choice, round the ends |
| `enter` | Plan |
| `esc` | Cancel; the frame closes the mode |
| On the note: text, a paste | Insert at the cursor; a control character or a line break enters as one space |
| On the note: `left` `ctrl+b`, `right` `ctrl+f`, `home` `ctrl+a`, `end` `ctrl+e` | Move the cursor by one code point, to the start, to the end |
| On the note: `backspace` `ctrl+h`, `delete` `ctrl+d`, `ctrl+u`, `ctrl+k` | Delete before or at the cursor; everything before it; everything after it |

The note editor is the package's own, a slice of runes and a cursor. Bubbles' text input stays out (D9).

**The form's lines**, as [`form-80x16.txt`](518e/form-80x16.txt) shows: the title `record <id> <title>`; a blank; `  now     <gate> <state>[, <reason>]` followed by ` · <note>` or by `, no status file`; a blank; the four fields; a blank; the messages. A field reads `> ` on the focused one and two spaces on the others, the label in 8 cells, then `< choice >` or the note. A field that takes no input draws muted: `the subproject states it`, `undefined, as the gate undefined requires`, `complete, at the last gate that applies`, or `none to choose` for a project with no state to choose. A body too short gives up lines in this order: the blank above the messages, the blank above the fields, the blank under the title, the `now` line, the title; at the floor of 40×8 the body holds the four fields and one message line ([`form-held-40x8.txt`](518e/form-held-40x8.txt)).

The focused note draws its cursor as one reversed cell, a space at the end of the text, inside the `width − 10` cells of the field: the text starts at the first code point, or at `…` and the first later one, from which the text up to the cursor and the cursor cell fit; the rest follows, cut with `…` ([`form-note-60x12.txt`](518e/form-note-60x12.txt)). Since reverse is a style, the status line states the cursor too.

The messages are the reason the last plan stopped: `refused:` or `no plan:`, then the lines of [Refusals and failures](#refusals-and-failures), each wrapped to `width − 2`, indented by two and drawn as an error; when they outrun the body, the last line reads `  … <n> more`. With no such reason, the uncommitted-edits line stands there, muted.

### The confirmation

The pager shows `Plan.String()` without its final line break, each tab as four spaces and no carriage return, each line wrapped to the width at spaces where it can and by cells where it cannot, so a long note in a diff stays readable. The first line draws as a header. Beneath it stands the footer, the prompt last:

| Line | When | Style |
|------|------|-------|
| `warning: <code>: <text>`, or `<n> warnings: <code>, <code>; the end of the plan states them` | The plan has one warning, or several | `Acts` |
| `uncommitted edits under .tableaux; the plan reads HEAD` | `Uncommitted` listed a path | `Muted` |
| `drawn for <viewer>; the commit is <author email>'s` | `Options.Viewer` is set and is neither the plan's author email nor its committer email | `Muted` |
| `Commit? y commits, n cancels` | Always | `Header` |

The pager takes the body less the footer; when that leaves four lines or more, a rule of `─` takes one of them above the footer. `y` commits. `n` and `q` close the mode with the notice `not committed`, tabloio's words; `esc` closes it through the frame. `enter` does nothing here, so two `enter`s in a row never commit (D5). `up` `k`, `down` `j`, `pgup`, `pgdown` `space`, `home` `g` and `end` `G` scroll, clamped in `Update` through `Context.Width` and `Context.Height`.

After `Apply` returns, whatever it returns, the command calls `Poke` and sends `ui.ReloadMsg{}`. On success the notice reads `committed <seven digits> <subject>` and the mode closes.

### Refusals and failures

The interface restores nothing and keeps no copy of a file: `Apply` makes the planned commit or leaves the checkout as it found it, as tabloio's design b618 states, which settles the prototype's finding in the package. The lines that state an error:

| The error holds | Lines |
|-----------------|-------|
| `action.Refusals`, or one `action.Refusal` | One per refusal: `<task> <gate>: <text> (<code>, <rule>)`, without the parts a refusal lacks |
| `*action.ExecError` | `<Tool> <Args[0]>: exit <Exit>`, then each line of `Stderr` |
| Any other error | The lines of its text |

| Where | Error | The screen | Notice |
|-------|-------|------------|--------|
| Plan of `v`, `a`, `u` | A refusal | `stopped`, headed `<name>: refused` ([`refused-80x12.txt`](518e/refused-80x12.txt)) | None |
| Plan of `v`, `a`, `u` | Any other | `stopped`, headed `<name>: no plan` | None |
| Plan of `r` | Any | The form again, with the messages ([`form-refused-80x16.txt`](518e/form-refused-80x16.txt)) | None |
| `Apply` | A refusal with no commit: `stale` | `stopped`, headed `<name>: refused`; after the lines, a blank and `nothing is written; close this and press the key again` | `error: not committed: <first line>` |
| `Apply` | An error beside a commit: `altered` | `stopped`, headed `<name>: committed <seven digits>, and a hook altered the commit` | `error: committed <seven digits>, and a hook altered the commit` |
| `Apply` | Any other: a hook, no identity, signing | `stopped`, headed `<name>: not committed`; after the lines, a blank and `the checkout stands as it stood before the commit` ([`failed-80x16.txt`](518e/failed-80x16.txt)) | `error: not committed: <first line>` |

`<name>` is `<command> <id>`, with the gate for a review. A `stopped` screen draws the head as an error, a blank, and the wrapped lines in a pager; `enter`, `n` and `q` close it, `y` does nothing, and the scroll keys scroll.

**The status line** of the mode: `<name> · <field> · <i> of <n>` on a choice and `<name> · note · cursor <p> of <n>` on the note; `<name> · planning…`; `<name> · committing…`; `<name> · lines <a>–<b> of <n>` in a pager. **The help line**: `enter plan`, `↑↓ field`, `←→ choice`, `esc cancel` in the form; `y commit`, `n cancel`, `↑↓ scroll` at the confirmation; `enter close`, `↑↓ scroll` when stopped; nothing while it plans or commits.

### Identity and trailers

`Repo.Env` stays nil: the commit takes the author and the committer Git would write for the person at the keyboard, and the plan prints both before the message. `Reviewed:`, `Authorised:` and `Reaffirmed:` come from the package, the self-review of `record` among them, so the prototype's toggle goes. The interface states no `action.Agent`, reads neither `TABLOIO_MODEL` nor `TABLOIO_CO_AUTHOR`, and has no `--model` and no `--co-author`: a person at a keyboard is no agent (D7). A hand that holds an agent's junction then meets the package's warning `model-missing` in the footer. The view may be drawn for another person than the hand; the action still commits as the hand, and the footer says so (D2).

### A quit during a commit

The frame quits on `ctrl+c` at any time. `Apply` therefore runs under a context that the end of the program does not cancel, and the command line calls `Wait` after the program returns and before it cancels its own context; when `Busy` is true it first prints `tablotui: a commit is in flight; waiting for git` to standard error. `Wait` covers an `Apply` that has begun (D12).

### Width, colour, determinism

Every line of the mode passes through `Context.Measure`, and the mode pads nothing through Lip Gloss. The wrap of a pager line is `Measure.Method.Wrap` of `Measure.Clean` of the line, since `Measure.Wrap` returns a fixed count of lines. The styles are the frame's: `Header`, `Muted`, `Error`, `Acts` and `Cursor`; a diff takes no colour, since `+` and `-` say it. `View` and `Status` are functions of the mode and the size: no clock, no map order, no terminal query. The mode starts no timer.

The prototype measured nothing: it drew through Lip Gloss v1 and fixed no width. The trial of this design, with no terminal, measured each line of 3 864 screens at its terminal width under `ansi.WcWidth` and under `ansi.GraphemeWidth` ([Tests](#tests), T14). Unverified, since nothing ran in a terminal emulator: how any emulator draws the reversed cursor cell, a note that holds a joined emoji sequence, and whatever a hook or a signing program writes to the terminal while Bubble Tea holds it.

### From the prototype

The design keeps the two commands, plan and apply, each off the event loop, and the keys. It keeps none of `write.go`: the package replaces the copy. It drops the task list, `--repo`, `--model` and `--name`; the self-review toggle; `enter` as a confirmation; the restore around `Apply`; and Lip Gloss as the measure. Its questions for the design gate settle so: the import, by b618 decision 1; the restore, in `Apply`; the form and the confirmation as one mode over the whole body, with a pager of the package's own; the role checks, D1; the trailers, D7; and the Charm major, v2 as it stands on `main`.

The checks the prototype skips, its question 4, land here:

| Check | Lands in |
|-------|----------|
| Who may record or reaffirm | The package warns `not-contributor`; the footer shows it |
| Who may review; a gate that does not apply | The package refuses `wrong-hand`, `gate-not-applicable`, `no-reviewer`, `recursive`, `defined-review` |
| Who may authorise; the trunk | The package refuses `wrong-hand` and `off-trunk` |
| A status that passes a gate before its review | The package refuses `unreviewed`, or adds `Reviewed:` for the reviewer's own hand |
| Reaffirm with no status; a parent | The package refuses `no-status` and `not-leaf`; row 8 above spares the form for a parent |
| A task that does not exist | The package refuses `no-task`; `Facts.Task` fails first for `r` |

## Conformance to the texts

- **README.md, Roles** and its last paragraph: a role is audit-only and the tool prevents no commit. The interface prevents none either; it declines only what the method cannot read, through the package's refusals (b618 decision 3).
- **README.md, Status**: `r` writes the status file through the package's line edit; `a` and `v` make the two empty commits the section shows; the hand-off is the reason `review` in the form; a contributor who is the reviewer gets `Reviewed:` on the recording commit.
- **README.md, Proposed and authorised tasks**: `u` is the third way to authorise. The first and the second, a commit of the task file and a merge, stay Git's.
- **SYNTAX.md, Commit trailers**: the package composes and proves them; the plan on screen shows the final paragraph as Git reads it.
- **VIEWS.md, Parameters**, as ruled on 2026-10-06: the default view reads the working tree. The texts are silent on what a write does while the tree differs from `HEAD`; rows 5 and 6 of [Before a plan](#before-a-plan) and D3 fill the gap.
- **Where two records differ.** VIEWS.md names the viewer "the email Git would commit with", and this repository's README offers `--as` for another participant. D2 follows the first for the commit and the second for the view.
- **No mockup** draws an action: the task's `mockup` junction does not apply.

## Decisions at review

1. **The interface checks no role.** It asks the package, shows a refusal and a warning as the package states them, and reads no role from the envelope. The alternative dims a key by `viewer.roles`, which hold across the project and not at the junction, and repeats in the interface a rule the package owns. Binds `b618` and `f394`. Accepted by the owner on 2026-10-07, as stated.
2. **An action commits as Git's identity**, whoever the view is drawn for, and the confirmation says so when the two differ. The alternative refuses every action under `--as`, which stops a reviewer who reads an agent's view from accepting its work there. Binds `f394`. Accepted by the owner on 2026-10-07, as stated.
3. **An uncommitted edit of the task's own status or task file refuses all four actions**, any other edit under `.tableaux` adds a line, and the interface runs the check, two git runs. The alternative puts the refusal `dirty` on every plan of the package, which serves the command line too and amends `b618`. Accepted by the owner on 2026-10-07, as stated.
4. **With `--ref` nothing writes**, `--ref HEAD` included. The alternative allows a write when the ref resolves to `HEAD`, a second rule for a rare case. Accepted by the owner on 2026-10-07, as stated.
5. **Only `y` commits.** `enter` does nothing at the confirmation, as tabloio's `Commit? [y/N]` reads it. The alternative is the prototype's: `enter` commits, and two `enter`s from the form make a commit. Accepted by the owner on 2026-10-07, as stated.
6. **The cursor is the argument.** `v` reviews the gate under the cursor with no form, and `r` takes a later gate under the cursor as its default. The alternative gives `v` a gate chooser, a second form for one field. Accepted by the owner on 2026-10-07, as stated.
7. **No agent trailer.** The interface states no model and no co-author and reads neither `TABLOIO_MODEL` nor `TABLOIO_CO_AUTHOR`. The alternative reads the two variables, for an agent that drives the interface, which none does. Binds `b618` decision 5. Accepted by the owner on 2026-10-07, as stated.
8. **The dependency on tabloio**, MIT: the `require` names a tabloio tag, the README's policy for tablo extends to tabloio word for word, and both front ends sit on one minor of tablo. The alternative requires a pseudo-version of tabloio's trunk, which needs no release and departs from the policy. Binds `b618` and tabloio's releases. Accepted by the owner on 2026-10-07, as stated.
9. **The note editor is the package's own.** Bubbles' text input stays out: it measures by grapheme whatever the terminal reports, starts a blink timer, and brings the module `github.com/atotto/clipboard`. The alternative takes it, as the README's dependency table foresees for a later task. Accepted by the owner on 2026-10-07, as stated.
10. **What the interface leaves to the command line**: `propose`, `--pin`, several tasks in one commit, `--message` and `--body`. The alternative adds a pin switch to the form for a task with a submodule junction. Accepted by the owner on 2026-10-07, as stated.
11. **The frame stays as it stands.** The four findings of [Implementation notes](#implementation-notes) change no code of `679b` now; `Options.Poke` answers the fourth from the command line. The alternative amends the frame: no tail on the help line in a mode, the commands on the help line, which changes the grid's goldens, and a frame that pokes on `ReloadMsg`. Binds `679b` and `171b`. Accepted by the owner on 2026-10-07, as stated.
12. **A quit waits for a commit in flight**: `Apply` runs under a context the quit does not cancel, and the command line waits and says so. The alternative lets the quit kill Git, which can leave written files with no commit. Accepted by the owner on 2026-10-07, as stated.
13. **The plan.** The requirement on `0afa` moves to `to: integrate`, and the integrate gate gains `171b` and `f394`, as [Implementation notes](#implementation-notes) states. The alternative keeps the task file as it reads. Accepted by the owner on 2026-10-07, as stated.

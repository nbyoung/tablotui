# Design f394: Role and context

The program learns who sits at the keyboard, asks tablo which roles that email holds, and starts the grid where the first of them works: the owner on the whole project at a glance, an assignee or a contributor on their own corner with the parents of their tasks unfolded, a reviewer on the whole project with their cells marked. `R` moves to the next role. Six choices shape it. The option is `--as`, and it defaults to the email Git commits with (D1, D2). A pane that never opens holds the role, so the frame changes by no line (D3). The request carries the viewer and the role and the source echoes them, so the grid's context line needs no change (D4). The grid gains one fold rule that reads the data and one start that waits, 40 lines in all (D5). `R` stops once per place, not once per role, and every viewer reaches the whole project as an observer (D6, D7). A switch keeps the column choices and the selection and returns everything else to the arrival's own state (D8). D*n* is decision *n* under [Decisions at review](#decisions-at-review).

The drafts under [`f394/`](f394/) fix the data, the screens and the Go text.

| Draft | Lands as | Holds |
|-------|----------|-------|
| [`context-person.json`](f394/context-person.json) | `internal/ui/grid/testdata/context-person.json` | The fixture: the person form of `context.md` at detail for nbyoung@nbyoung.com, 14 rows, four of them siblings, window 📝 to 📏 |
| Six `*.txt` files, listed under [T1](#tests) | `internal/ui/role/testdata/` | The golden screens |

The fixture is hand-made from the mockup and from the grid's `tableau-person.json`, in the form of [design 679b](679b.md). It is no output of tablo.

## The model

### Packages

| Path | Holds |
|------|-------|
| `internal/identity/` (new) | `Email`: the viewer's email from `--as` or from Git |
| `internal/ui/role/` (new) | The role pane, the `R` command, `Stops` and `Arrival` |
| `internal/view/` | Gains `Viewer` |
| `internal/source/` | `Request` gains `Viewer` and `Role`; gains the `Viewers` interface, which `File` implements; `File` echoes the two fields |
| `internal/ui/grid/` | `Start` gains `Mine`; a start that names no view waits |
| `cmd/tablotui/` | Gains `--as` and wires the role pane and its command |

`internal/ui` does not change. `role` imports `grid`, `source`, `ui` and `view`; nothing imports `role` but `cmd`.

### Who looks

```go
package identity

// ErrUsage marks an error that the command reports with exit status 2.
var ErrUsage = errors.New("usage")

// Email returns the viewer's email: as, when it is not empty; else the
// environment's GIT_AUTHOR_EMAIL; else what "git -C dir config --get
// user.email" prints; else "", which is nobody. It refuses an as that is no
// email, one "@" with text on both sides and no space, with an error that
// wraps ErrUsage. A git that is missing, fails or states no email gives "".
func Email(ctx context.Context, dir, as string) (string, error)
```

```
tablotui [-C <dir>] [--as <email>] [--settings <file>] [--fixture <dir>] [--version] [--help]
```

The command calls `Email` once, after it checks `-C` and before the program takes the screen. The order is tablo's own for its `--viewer` ([4ed9](https://github.com/nbyoung/tablo/blob/main/design/4ed9.md), "The viewer"), so the plumbing and this front end name the same person in the same shell. The program never reads the identity again: a `git config` edit during a session shows at the next start. A refused `--as` prints `tablotui: usage: --as <value>: not an email` and exits 2. `--as` changes who looks and never who commits: Git writes a commit with its own identity (A12).

Nobody, the empty email, is an observer. The program then asks tablo nothing about roles, starts on the observer's arrival, names no viewer in the context line, and says once in the status line `no Git identity: reading as an observer; pass --as <email>`. An email that appears nowhere in the project is an observer too, by tablo's answer, and the context line reads `viewer eve@example.org, observer`.

tablotui takes no `--person`. On the two arrivals that focus a person, the person is the viewer; `--as ben@example.org` shows Ben's corner, as the README's example reads.

### What tablotui passes and what it reads back

```go
package view

// Viewer is the person at the keyboard as tablo sees them: the email, and the
// roles that email holds anywhere in the project, in tablo's order. Roles is
// "observer" alone when the email holds none.
type Viewer struct {
	Email string   `json:"email"`
	Roles []string `json:"roles"`
}
```

```go
package source

type Request struct {
	// … the seven fields on main, unchanged …
	Viewer string // the email of the person at the keyboard; "" is nobody
	Role   string // the role the viewer reads as; "" is the viewer's own
}

// Viewers names the roles an email holds in the project at a ref. A call
// blocks; the role pane runs it in a command.
type Viewers interface {
	Viewer(ctx context.Context, ref, email string) (view.Viewer, error)
}

// Viewer implements Viewers from viewers.json in Dir, an object that maps an
// email to its roles. A missing file, and an email the file lacks, give an
// observer.
func (f File) Viewer(ctx context.Context, ref, email string) (view.Viewer, error)
```

| tablotui passes | To tablo (4ed9) | It reads back | Into |
|-----------------|-----------------|---------------|------|
| The email, once per load of the roles | `Snapshot.Viewer(email)` | `email`, `roles` | `view.Viewer`, which the role pane keeps |
| `Request.Viewer`, on every tableau | `Params.Viewer` | `viewer.email` of the envelope | `view.Tableau.Viewer` |
| `Request.Role`, on every tableau | `Params.Role` | `params.role` of the envelope | `view.Tableau.Role` |
| `Request.Level`, always `detail` or `provenance`, as the grid sets it on `main` | `Params.Level` | The rows of that level | The grid |
| `Request.Person`, the viewer's email on two arrivals, empty on the third | `Params.Person` | The rows, the labels, the marked cells | The grid |

tablotui derives no role. tablo names the roles an email holds; the viewer chooses among them with `R`; the role in force travels to tablo and comes back in the data, where the grid's `Headline` already prints it. Since the grid states the level on every request, tablo's resolution of a level from a role (4ed9 decision 6) never decides what tablotui draws: the role chooses the arrival, below, and nothing else.

A source echoes: an answer states the `Viewer` and the `Role` of its request. `File.Tableau` sets the two fields on the tableau it decodes when the request states them, and `File.Name` ignores both, so the twelve goldens of 679b stand. The tablo adapter echoes through the envelope (A9).

### The role pane

```go
package role

// ID is the identifier of the role pane. The pane never opens.
const ID = "role"

// The roles, as tablo names them.
const (
	Owner, Authority, Assignee, Contributor = "owner", "authority", "assignee", "contributor"
	Agent, Reviewer, Observer               = "agent", "reviewer", "observer"
)

// Stops returns the roles that R cycles through: of the roles held and
// observer, in the naming order, the first that leads to each place.
func Stops(roles []string) []string

// Arrival is where the viewer starts in a role. An unknown role, and "",
// arrive as an observer does.
func Arrival(role, viewer, ref string) grid.Start

// SwitchMsg asks the role pane for the next stop.
type SwitchMsg struct{}

// Command binds R to the switch of role: its Run returns a SwitchMsg.
func Command() ui.Command

// Options configures the role pane. An empty Viewer is nobody: an observer.
type Options struct {
	Source source.Viewers
	Viewer string
	Ref    string // "" is the checkout; 171b's integration sets it from --ref
}

// Pane holds the viewer, the stops and the stop in force. It implements
// ui.Pane, draws nothing and never opens.
type Pane struct{ /* src, viewer, ref, seq, stops, at, arrived, selected */ }

// New builds the role pane.
func New(o Options) Pane

// Role returns the role in force, or "" before tablo names the roles.
func (p Pane) Role() string
```

The command wires it after every other pane, and gives the grid no start:

```go
src := source.File{Dir: inDir(*dir, *fixtures)}
g := grid.New(grid.Options{Source: src, Settings: path})      // the zero Start waits
who := role.New(role.Options{Source: src, Viewer: email})
opts := ui.Options{Panes: []ui.Pane{g, who}, Commands: []ui.Command{role.Command()}, …}
```

The frame calls `Init` on every pane, broadcasts to every pane, and delivers a `LoadedMsg` to the pane it names, open or not; it draws, focuses and lists the keys of open panes alone. Nothing opens the pane `role`, so it is a holder of state that lives by the frame's own rules: `Keys` is nil, `Status` is empty, and `View` returns blank lines. `Command.Run` cannot hold the role, since a command is a function and keeps nothing between two keys.

| On | The pane | Returns |
|----|----------|---------|
| `Init`, a viewer | — | A load of the roles through `Context.Load(ID, seq, …)` |
| `Init`, nobody | (`New` sets the stops to `observer`) | `grid.StartMsg` with the observer's arrival, and the notice above |
| `LoadedMsg`, the first good answer | Sets the stops; stands at the first | `grid.StartMsg` with the first stop's arrival, `Select` the selection, if any |
| `LoadedMsg`, a later good answer, the role in force still a stop | Takes the new stops; stays | Nothing |
| The same, the role in force no longer a stop | Takes the new stops; stands at the first | `grid.StartMsg`, and `the role <was> no longer holds: reading as <role>` |
| `LoadedMsg` with an error, before any arrival | Notes that the grid has a start | `grid.StartMsg` with `Arrival("", viewer, ref)`, and `error: roles: <message>` |
| `LoadedMsg` with an error, later | Keeps the stops | Nothing: the grid reports its own load |
| `LoadedMsg` with another `Seq` | Nothing | Nothing |
| `ui.ReloadMsg`, a viewer | Raises `seq` | A load of the roles |
| `ui.SelectionMsg` | Keeps the task | Nothing |
| `SwitchMsg`, no stops yet | Raises `seq` | A load of the roles, and `the roles have not loaded; asking again` |
| `SwitchMsg`, one stop | Nothing | `one role only: <role>` |
| `SwitchMsg`, several | Stands at the next stop, the first after the last | `grid.StartMsg` with its arrival and `Select` the selection, and `reading as <role>, <i> of <n>` |

So the roles follow the project: a reload asks again, and a person who gains a first task finds the new stop at the next `R`, and the screen stays where it is meanwhile. The program loads one tableau at the start, not two, because the grid waits for the pane's first `StartMsg`.

### Stops and arrivals

A **place** is a view with the state it opens in. Three exist:

| Place | Roles that lead to it | `Request` | `Level` | Folds and selection |
|-------|-----------------------|-----------|---------|---------------------|
| The whole project | `owner`, `observer`, any role this list lacks, and `""` | `View` `tableau`, no `Person` | `Glance` | The root and its children; the first row. Equal to `grid.GlanceStart()` but for viewer, role and ref |
| The corner | `assignee`, `contributor`, `agent`, `authority` | `View` `context`, `Person` the viewer | `Detail` | `Mine`: the parents above the viewer's own tasks; the first of those tasks |
| The marked project | `reviewer` | `View` `tableau`, `Person` the viewer | `Glance` | `Mine`: the parents above the rows where the viewer acts; the first such row |

Every request also states `Window` 1, `Historical` false, `Level` `detail`, the viewer, the role and the ref. tablo computes the window around the next gates of the tasks in view; tablotui asks for its default width and computes no gate.

`Stops` walks `owner`, `assignee`, `contributor`, `agent`, `authority`, `reviewer`, `observer`. It skips a role the viewer does not hold, except `observer`, which it never skips, and keeps the first role that leads to each place. So the cycle has one to three stops:

| tablo names | Stops |
|-------------|-------|
| `owner`, `authority`, `assignee`, `reviewer` (the owner of this plan) | `owner`, `assignee`, `reviewer` |
| `authority`, `assignee`, `contributor`, `agent` (the agent of this plan) | `assignee`, `observer` |
| `assignee`, `contributor`, `reviewer` | `assignee`, `reviewer`, `observer` |
| `reviewer` | `reviewer`, `observer` |
| `owner` | `owner` |
| `observer` | `observer` |

The program starts at the first stop and `R` takes them in order, round. A person who is the owner and an assignee starts as the owner, as the prototype has it. `authority` names the corner last, since the corner shows what a person is assigned or contributes at, which `assignee` and `contributor` say. The stop `observer` gives every viewer the global tableau, which "every role reads" (VIEWS.md); the owner already stands there. The prototype's question of a preview has this answer: the observer's reading for all, and no reading as a role the viewer does not hold.

### The grid's two additions

```go
type Start struct {
	Request source.Request
	Open    []string
	Select  string
	Level   Level
	// Mine takes the folds from the data: it unfolds every parent above a row
	// that is the person's, and selects the first such row unless Select
	// names a row. A row is the person's when it carries no label in a
	// contextual tableau, and when the person acts in one of its cells in a
	// global one. With no such row, Open decides.
	Mine bool
}
```

1. **`Mine`.** The parents of a person's tasks are a fact of the data, and a `Start` exists before the data does. `arrive` therefore reads them when `Mine` is set: it walks the rows once with the stack of ancestors, unfolds each ancestor of a row that is the person's and of no other row, and selects the first such row. `Select`, when the data holds its row, still wins. A parent that is the person's own and has no task of theirs beneath it stays folded, as `2034 Views` does in `context.md`.
2. **A start that waits.** `Grid.load` returns no command for a request whose `View` is empty. A grid built with the zero `Start` so reads `loading…`, ignores keys as it does before any data, asks nothing on a `ReloadMsg`, and loads at the first `StartMsg`. `grid.GlanceStart()` and every test on `main` name a view and behave as before.

Nothing else in the grid changes. [`model.md`](f394/model.md) holds the diff: 40 lines.

### What a switch keeps

| State | At a switch |
|-------|-------------|
| The column choices, in the settings file and in memory | The switch keeps them: `grid.start` touches neither, and the file's bytes do not change |
| The selection | The switch keeps it where the new data holds its row. A row the arrival's folds hide moves the selection to the nearest row above, by the grid's rule on `main`. A row the data lacks gives the arrival's own selection |
| The unfolded rows | The arrival's replace them |
| The window width set by `w` and `W`, and the historical switch | Return to window 1 and off: the request is the arrival's |
| The strip | The arrival's level. Once the viewer has opened provenance the grid keeps asking for it, as on `main` |
| The column cursor | Returns to the task column, as `grid.start` does on `main` |
| `--ref` | Every arrival states `Options.Ref` |
| The repository | This task writes nothing into it, and nothing anywhere but what the grid already writes to the settings file |

### Errors and determinism

`Email` fails on a malformed `--as` alone. A roles load that fails never ends the program and never leaves the grid waiting: the pane starts the grid on the whole project with no role, and the next reload or the next `R` asks again. `Stops` and `Arrival` are pure functions; the pane reads no clock; the same fixture, viewer, size and keys give the same bytes.

### Width and the terminal

The role pane draws nothing, and the grid and the frame draw every cell through `Context.Measure`, so this task adds no measured text but the context line's ` · viewer <email>, <role>`, which is ASCII, and the notices. [Prototype f394](../prototype/f394/README.md) printed gate keys in place of symbols and measured nothing. The trial measured each line of the six goldens under `ansi.WcWidth` and `ansi.GraphemeWidth`, and each line of four key scripts at 105 sizes from 40×8 to 138×38 under `ansi.WcWidth`: every line has the terminal's width. No trial ran in a terminal emulator, so the design claims none.

One flaw shows: the frame cuts the context line on the right, so the role goes first. `narrow-60x16.txt` ends `· viewer nby…`, and at 80 columns `Tableaux tooling · main at 3cdae52, 2026-10-05 · viewer noreply@anthropic.com, …` loses the role alone. The notice names the role at each switch and the next key clears it. `Headline` belongs to 679b; this design leaves it and reports the flaw.

### From the prototype

The design keeps `--as` and the Git default, the owner first for a person who holds several roles, the observer in the owner's layout, the notice `one role only`, and the rule that a switch leaves the hidden columns alone. It drops the join of three views that derived the owner, the assignments and the next gates, since tablo names the roles and computes the window; the lower-case `r`, which 518e holds; and `--dump`, `--keys` and `--chrome`. The prototype's list "What the view data does NOT carry" becomes A1 to A8.

## Conformance to the texts

- **[VIEWS.md, Parameters](https://github.com/nbyoung/tableaux/blob/main/VIEWS.md#parameters), the viewer.** "Whoever runs the tool, identified by the email Git would commit with": `Email`. "An observer has no email in the project": tablo's answer, or nobody.
- **The person parameter.** tablotui names the person on every request and relies on no default, as tabloio does (5ca9 A9): the viewer on the corner, nobody on the owner's and the observer's global tableau, the viewer on the reviewer's, where "person marks the cells where the person acts".
- **The role parameter.** "The role whose level the view opens at": the request states it and tablo echoes it; the explicit level the grid sends overrides the level it would open.
- **[Global tableau](https://github.com/nbyoung/tableaux/blob/main/VIEWS.md#global-tableau)**, "the owner and an observer; every role reads it", and `tableau.html`, "the page opens on the root and its children … closed on arrival for the owner", "an observer sees this page as drawn, with no person to mark": the first place.
- **[Contextual tableau](https://github.com/nbyoung/tableaux/blob/main/VIEWS.md#contextual-tableau)**, "an assignee and a contributor; an authority, for its subtree", and `context.html`, "a contributor arrives at the person form below, with the parents of their tasks open", an assignee "at detail and each provenance closed": the second place. `corner-100x24.txt` draws the detail table of `context.md`'s person form, row for row.
- **[README.md, Roles](https://github.com/nbyoung/tableaux/blob/main/README.md#roles).** The seven role names, and "holds several at once": the stops.

Where the texts are silent or disagree:

- **A reviewer on a tableau.** No text names a tableau for a reviewer; VIEWS.md gives the reviewer the queue, the task view and the history. The third place is this design's reading of "person marks the cells where the person acts" (D6).
- **An authority's subtree.** The task form needs a task, and tablo's `Viewer` names roles, not tasks. An authority arrives on the corner, where their assigned parents stand as their own rows (D6). `Request.Task` stays unset by this task.
- **The task's description** says "the tree collapsed" and "the parents of their assigned tasks". `tableau.html` and 679b read the first as the root and its children; VIEWS.md reads the second as the tasks "assigned or contributes at next", which tablo decides.
- **The owner's window.** The prototype asked whether the window follows every task or the rows unfolded. VIEWS.md says "every task in view"; the global tableau has every task in view, and tablo computes it.
- **Which email Git commits with.** VIEWS.md does not say author or committer. tablo reads the author's, and so does this design.

## Decisions at review

1. **The option is `--as`.** It names the viewer, as this repository's README writes it and as the owner ruled for tableaud (49ce decision 2: "`--as` names the viewer alone"); the two live front ends then share the word, and `--person` stays the person a view focuses. The alternative is `--viewer`, tablo's own word for the plumbing (4ed9), which gives one word across the library and the front ends and changes the README here and tableaud's option. Binds 49ce and 4ed9. Accepted by the owner on 2026-10-07, as stated.
2. **The default identity.** `--as`, else `GIT_AUTHOR_EMAIL`, else `git config user.email` in `-C`, read once at the start; nobody is an observer, with one notice. The order is tablo's (4ed9). The alternative is tableaud's (49ce): `--as`, else `user.email`, which ignores the variable Git itself honours. Binds 49ce, which then differs from tablo and from this design. Accepted by the owner on 2026-10-07, as stated.
3. **A pane that never opens holds the role**, and the frame changes by no line. The alternative gives `ui.Options` a list of services that receive messages and draw nothing, which says the same in the frame's own vocabulary and changes 679b's code. Binds 0afa (A11) and 518e. Accepted by the owner on 2026-10-07, as stated.
4. **The seam gains the viewer.** `source.Request` gains `Viewer` and `Role`, a source echoes them into the tableau, and `source.Viewers` answers with the roles. The alternative binds the viewer to the source when the command builds it and wraps the source to stamp the role, which keeps `Request` as it stands and puts changing state behind a call that runs off the event loop. Binds 679b and its adapter (A9). Accepted by the owner on 2026-10-07, as stated.
5. **The grid gains `Start.Mine` and a start that waits**, 40 lines in `internal/ui/grid/grid.go`. The alternative changes no line of the grid: the role pane loads each tableau first, lists the parents itself and passes them in `Start.Open`, at the cost of two loads for every arrival, and the grid then starts on the observer's view and redraws when the roles arrive. Binds 679b. Accepted by the owner on 2026-10-07, as stated.
6. **Three places.** The owner and an observer arrive on the global tableau at a glance; an assignee, a contributor, an agent and an authority on the person form at detail, the parents of their tasks unfolded; a reviewer on the global tableau with their cells marked and the parents of those rows unfolded. The alternative for the reviewer is tableaud's: the person form, which is empty for a person who reviews and holds no task. The alternative for the authority is the task form of their subtree, which needs tablo's `Viewer` to name the tasks, an amendment of 4ed9. Binds 49ce (A13) and 886d. Accepted by the owner on 2026-10-07, as stated.
7. **`R` stops once per place, and every viewer may read as an observer.** The stops take their names in the order owner, assignee, contributor, agent, authority, reviewer, observer. The alternatives: the roles held alone, as the prototype has it, which leaves a contributor no way to the whole project but `--as` with a stranger's email; or one stop per role, which shows a person with four roles the same corner four times and folds it again each time. Accepted by the owner on 2026-10-07, as stated.
8. **A switch keeps the column choices, the selection and the ref, and resets the folds, the window width, the historical switch and the strip.** An arrival is a place to start, and its window is the default tablo computes. The alternative carries the width and the switch across, which needs the grid to report them, one more message in 679b's code. Accepted by the owner on 2026-10-07, as stated.

# Design 679b: Tableau grid

The grid draws the global tableau full screen: the task tree with fold and unfold, a gate window whose columns the viewer hides or shows, and a strip beneath that discloses the detail and the provenance of the selection. Three later tasks build on it, so this design also fixes the application's frame: the root model, how a pane, a mode or a command plugs in, focus, keys, sizing, colour, and the message that carries view data in. Four choices shape it. The program runs on the Charm v2 modules, because v2 tells the model how the terminal measures a symbol (D1). A hidden column folds exactly as a column outside the window does, and every fold shows its count in the header (D2, D3). The grid derives nothing: it draws what tablo sends and asks again when a parameter changes. The implementation draws from fixture files through one `Source` seam, and the tablo adapter lands at the integrate gate (D7).

The drafts under [`679b/`](679b/) fix the data and the screens; each lands under `internal/ui/grid/testdata/` with its name unchanged.

| Draft | Holds |
|-------|-------|
| [`tableau.json`](679b/tableau.json) | The fixture: the 37 rows of the approved mockup `tableau.md`, window 1, with provenance facts on four cells |
| [`tableau-window0.json`](679b/tableau-window0.json), [`tableau-historical.json`](679b/tableau-historical.json), [`tableau-person.json`](679b/tableau-person.json), [`tableau-empty.json`](679b/tableau-empty.json) | The same rows under each variation of the mockup, and a project with no task |
| Twelve `*.txt` files, listed under [T1](#tests) | The golden screens: the exact text the program draws for a fixture, a size and a key sequence |

### The view data

```go
package view

// Tableau is one tableau, global or contextual, as tablo derives it. The grid
// draws it and derives nothing from it. Viewer and Role are optional (f394).
type Tableau struct {
	View       string `json:"view"`    // "tableau" or "context"
	Project    string `json:"project"` // the root task's title
	Ref        string `json:"ref"`
	Commit     string `json:"commit"`
	Date       string `json:"date"` // of the commit
	Viewer     string `json:"viewer"`
	Role       string `json:"role"`
	Level      string `json:"level"`
	Window     int    `json:"window"`
	Historical bool   `json:"historical"`
	Person     string `json:"person"`
	Gates      []Gate `json:"gates"` // every gate of the project, in order
	Rows       []Row  `json:"rows"`  // every row in view, in display order
}

// Gate is one gate column. Window says whether the window shows it; Count is
// the number of tasks in view whose current gate it is.
type Gate struct {
	Key, Symbol, Name string
	Window            bool
	Count             int
}

// Row is one task. Label is "", "spine" or "sibling". Cells holds one cell
// per gate, in gate order, whatever the window.
type Row struct {
	ID, Title string
	Depth     int
	Parent    bool
	Label     string
	Status    Status
	Cells     []Cell
}

// Status is the row's status, stated or rolled up. From is nil for a leaf
// that states its own status.
type Status struct {
	Gate, State, Reason, Date, Note string
	From                            *From
}

// From names where a derived status comes from. Kind is "rollup" (ID and
// Title of the deciding leaf) or "snapshot" (ID and Title of the subproject's
// root, the Pin, and the Gate it stands at there).
type From struct{ Kind, ID, Title, Pin, Gate string }

// Cell is one gate cell. Kind is "status", "marks", "exempt" or "historical".
// Symbols is the text to draw, empty for a historical cell while the
// historical-junctions parameter is off. Acts marks a cell where the person
// acts. Facts is the provenance, present at the provenance level.
type Cell struct {
	Kind, Symbols string
	Acts          bool
	Facts         []Fact
}

// Fact is one line of provenance: "Deciding commit", "3d8ce0e Record …".
type Fact struct{ Label, Text string }

// Decode reads one tableau and refuses a row whose cells do not match the
// gates one for one, a depth that rises by more than one, and an unknown kind.
func Decode(r io.Reader) (Tableau, error)
```

Every field carries a lower-case `json` tag of its own name, as the fixtures show; the block spells out the first struct only.

```go
package source

// Request names one tableau and the parameters that focus it (VIEWS.md, Parameters).
type Request struct {
	View       string // "tableau" or "context"
	Ref        string // "" is the checkout; 171b sets it
	Task       string // the contextual tableau's task form; f394 sets it
	Person     string // the person form, or the person a global tableau marks
	Window     int
	Historical bool
	Level      string // "detail" or "provenance"
}

// Tableaux loads a tableau. A call blocks; the frame runs it in a command.
type Tableaux interface {
	Tableau(ctx context.Context, r Request) (view.Tableau, error)
}

// File serves fixtures from Dir. The file name is the view, then "-window<n>"
// when Window is not 1, "-historical" when Historical, "-person" when Person
// is set, then ".json". A missing file is an error.
type File struct{ Dir string }
```

The grid always asks for every row (`detail`) and folds rows itself, so the tree keys cost no load. It asks for `provenance` from the first time the viewer opens provenance. A change of window or of the historical switch is a new request: tablo computes the window and the marks, and the grid keeps the last good view on screen until the answer arrives.

### The frame

```go
package ui

// Pane is one region of the body. View returns exactly h lines of exactly w
// cells under c.Measure. Update receives the keys while the pane has focus,
// the LoadedMsg addressed to it, and every other message.
type Pane interface {
	ID() string
	Init(c Context) tea.Cmd
	Update(msg tea.Msg, c Context) (Pane, tea.Cmd)
	View(w, h int, c Context) string
	Status(c Context) string // the status line while the pane has focus
	Keys() []key.Binding     // for the help line and the help mode, in order
}

// Headliner is a home pane that supplies the context line.
type Headliner interface{ Headline(c Context) string }

// Mode takes the whole body and every key but ctrl+c and esc: a form, a
// confirmation, the help. Update returns nil to close the mode.
type Mode interface {
	Update(msg tea.Msg, c Context) (Mode, tea.Cmd)
	View(w, h int, c Context) string
	Status(c Context) string
	Keys() []key.Binding
}

// Command is a global key that acts on the selection: an action, a role switch.
type Command struct {
	Binding key.Binding
	Run     func(sel SelectionMsg) tea.Cmd
}

// Context is what the frame lends a pane or a mode on every call.
type Context struct {
	Styles  Styles
	Measure Measure
	Focused bool
	// Load runs f off the event loop and delivers its result as a LoadedMsg.
	Load func(pane string, seq uint64, f func(context.Context) (any, error)) tea.Cmd
}

// Rect places one open pane in the body. Layout returns rectangles that tile
// the body exactly, with no overlap and no gap.
type Rect struct {
	Pane       string
	X, Y, W, H int
}
type Layout func(w, h int, open []string, focus string) []Rect

// Options configures the frame. The first pane is the home pane: it is always
// open, opens focused, and esc returns to it. A nil Layout gives the home
// pane the whole body. A nil Context is context.Background.
type Options struct {
	Panes    []Pane
	Commands []Command
	Layout   Layout
	Styles   Styles
	Context  context.Context
}

// New builds the root model. Model implements tea.Model.
func New(o Options) Model

// CheckKeys reports a key that two bindings share among the frame's own keys,
// the commands and one pane, for each pane.
func CheckKeys(o Options) error
```

The messages, all in `internal/ui`:

| Message | Sent by | The frame |
|---------|---------|-----------|
| `LoadedMsg{Pane string; Seq uint64; Value any; Err error}` | `Context.Load` | Delivers it to the pane it names. The pane drops a `Seq` that is not its newest. This message carries fresh view data in. |
| `ReloadMsg{}` | The watcher (171b); a command after a write (518e) | Broadcasts it. Each pane answers by loading its current request again. |
| `SelectionMsg{Task, Gate string}` | The home pane, on every change of row or cell and after every load | Keeps the latest for `Command.Run` and broadcasts it, so panes follow. `Gate` is empty off a gate cell. |
| `NoticeMsg{Text string; Err bool}` | Anyone | Shows the text in the status line until the next key. An error reads `error: <text>`. |
| `OpenModeMsg{Mode Mode}` | Anyone | Opens the mode. |
| `ShowPaneMsg{Pane string; Show bool}`, `FocusMsg{Pane string}` | Anyone | Opens, closes or focuses a pane. Closing the focused pane focuses the home pane. |

`Update` routes in this order. `tea.WindowSizeMsg` sets the size. `tea.ModeReportMsg` sets the measure ([Width](#width)). A key goes to the open mode after `ctrl+c` (quit) and `esc` (close); with no mode it goes to the frame's keys, then the commands, then the focused pane. Every other message goes to every pane and to the mode.

`View` returns a `tea.View` with `AltScreen` set and this content, every line exactly as wide as the terminal:

| Lines | Content |
|-------|---------|
| 1 | The context line, from the home pane: `Tableaux tooling · main at 3cdae52, 2026-10-05`, then ` · viewer <email>, <role>` when the data states them |
| 2 to height−2 | The body: the mode, or the open panes in their rectangles |
| height−1 | The status line: the notice, else the mode's or the focused pane's status |
| height | The help line: the bindings of the focused pane or the mode, joined by two spaces, dropped from the end until `? help  q quit` still fits after them |

Below 40 columns or 8 lines the frame draws one line, `tablotui needs 40×8, has <w>×<h>`, and no pane. A resize changes only the size the frame passes to `View`; no pane stores a width.

### Keys

| Scope | Keys | Does |
|-------|------|------|
| Frame | `q`, `ctrl+c` | Quit |
| Frame | `?` | Open the help mode: every binding by scope, with its help text |
| Frame | `tab`, `shift+tab`, `esc` | Focus the next or the previous open pane; return to the home pane |
| Grid | `up` `k`, `down` `j`, `pgup`, `pgdown`, `home` `g`, `end` `G` | Move the row cursor: by a row, by the rows in view, to the first or the last row |
| Grid | `left` `h`, `right` `l` | Move the column cursor: the task column, then each column in view |
| Grid | `enter`, `space` | Fold or unfold the selected parent |
| Grid | `E`, `C` | Unfold every row; fold to the root and its children |
| Grid | `d`, `p` | Open or close the detail strip; open provenance or return to detail |
| Grid | `x`, `s`, `X` | Hide the gate column at the cursor; show a gate of the folded column at the cursor; return to the window |
| Grid | `w`, `W` | Widen or narrow the window by one column either side |
| Grid | `H` | Switch the historical junctions on or off |
| Reserved | `1` to `4`, `z` (0afa); `R` (f394); `r`, `v`, `a`, `u` (518e) | Nothing in this task; no binding here takes them |

The help line of the grid reads, in order: `↑↓ row`, `←→ column`, `enter fold`, `E all`, `C glance`, `d detail`, `p provenance`, `x hide`, `s show`, `X window`, `w/W widen/narrow`, `H historical`. The prototype's positional digits go: a digit names a different gate in each window, and provenance needs a cell cursor in any case (D6).

### The grid

```go
package grid

type Level int

const (
	Glance Level = iota
	Detail
	Provenance
)

// Start is an arrival state. Open lists the unfolded parents; nil unfolds
// depth 0 alone. Select names a row; "" selects the first.
type Start struct {
	Request source.Request
	Open    []string
	Select  string
	Level   Level
}

// GlanceStart is the arrival of an observer and of the owner: the global
// tableau, window 1, historical off, the root and its children, no strip.
func GlanceStart() Start

// StartMsg applies a start to a running grid. It leaves the column choices alone.
type StartMsg struct{ Start Start }

// Options configures the grid. An empty Settings path keeps no choice.
type Options struct {
	Source   source.Tableaux
	Settings string
	Start    Start
}

// New builds the grid pane, with the ID "grid". It implements ui.Pane and ui.Headliner.
func New(o Options) Grid
```

**Columns.** A gate shows when the viewer's choice for it is `show`, or when the viewer states no choice and the gate's `Window` is true. Each shown gate is one column headed by its symbol. Each maximal run of gates that do not show is one folded column: its header is the symbol of a single gate or `first…last` for a run, then ` ×` and the sum of the run's counts, so `❔ ×0`, `❔…📝 ×29`, `🔧…📐 ×4`. Its cells are empty. The prototype's separate `⊘n` column goes (D3).

`x` on a gate column records `hide` when the window shows that gate, and otherwise forgets its `show`. `s` on a folded column takes the last gate of the run when the column is the first gate column of the grid, else the first gate of the run; it records `show` when the window folds that gate, and otherwise forgets its `hide`. `X` forgets the choice for every gate of this project. On any other column `x` and `s` change nothing and say so: `the cursor is not on a gate column`, `the cursor is not on a folded column`. Each change saves the settings before `Update` returns.

**Rows.** A row reads id, then the task label: two spaces per depth, `▾ ` for an unfolded parent, `▸ ` for a folded one, two spaces for a leaf, the title, ` · spine` or ` · sibling` from `Label`, and ` (n)` on a folded parent, where n counts the rows folded beneath it (D8). A parent's label draws bold. A gate cell draws `Symbols`, inside `[` `]` when `Acts`.

**Widths.** The id column is as wide as the widest id, at least 2. A gate column is as wide as the widest of its header and its cells over every row, folded or not, at least 2; a folded column is as wide as its header. One space separates columns. The task column takes its natural width, the widest label any row can have with its count, at least 4, when the pane allows it; else what remains, down to 12. Below 12 it stays at 12 and the gate columns scroll sideways: the grid draws, from a first column on, as many columns as fit whole, at least one. The first column is the one drawn before, lowered until no column that precedes it would also fit with all that follow, then moved by the least that brings the cursor column into view. The status then gains `columns 3–9 of 10`. A label that does not fit ends in `…`. Headers and cells sit centred, with the odd cell on the right; id and task sit left. The rule under the header repeats `─` per column. The grid computes widths when data, choices or the measure change, not on every draw.

**Height.** The pane holds the header, the rule, the rows and the strip. The strip takes 0 lines at glance, 5 at detail and 10 at provenance. When fewer than 3 rows would remain, the grid draws the next smaller strip. The rows scroll by the least that keeps the selection in view; `Update` settles both scroll offsets after every message, so `View` changes no state. The selection is a task id: it survives a reload, and when its row leaves the data or folds away it moves to the nearest row above.

**The strip.** At detail: a rule; `<id> <title> · <gate symbol> <gate> <status cell> <state>[, <reason>] · <date>`; the note on two lines, wrapped at spaces, the second ending ` …` when the note is longer; then `rolled up from <id> <title>`, or `snapshot of <id> <title> at pin <pin>, <symbol> <gate> there`, or, when the cursor stands on a folded column, `folded: ❔ undefined 0 · 📝 defined 29`, its counts gate by gate. At provenance, five more lines: `provenance of <id> at <symbol> <gate>` and the cell's facts as `  <label>: <text>`, the first three and `  … n more` when it has more than four. Off a gate cell it reads `move the column cursor to a gate cell`; on a cell with no fact, `this cell holds no fact`.

**Levels.** `d` opens the strip from glance and closes it from detail or provenance. `p` opens provenance from glance or detail and returns to detail from provenance.

**Status line.** `<id>[ × <symbol> <gate> | × <fold header>] · [columns a–b of n · ]rows a–b of n · window <n>[, <k> changed] · historical on|off`, where k counts the gates of this project that carry a choice. With no row it starts at `rows 0 of 0`.

**Requests.** `w` and `W` ask for the window one wider or narrower; at window 0, or when the window shows every gate, they say so and ask nothing. `H` asks with the switch reversed. Each request takes the next sequence number. A failed load keeps the view and shows `error: <message> (showing the last good view)`. Before the first answer the pane reads `loading…`; a first load that fails reads `error: <message>`; a tableau with no row draws its header and `no task in view` (D9).

### Width

```go
package ui

// Measure counts terminal cells the way the terminal in use draws them.
type Measure struct{ Method ansi.Method }

func (m Measure) Width(s string) int                 // of Clean(s)
func (m Measure) Clean(s string) string              // see below
func (m Measure) Fit(s string, w int) string         // cut with "…", pad right
func (m Measure) Centre(s string, w int) string      // pad both sides
func (m Measure) Wrap(s string, w, n int) []string   // see below
```

The frame starts with `ansi.WcWidth`, which counts code points as a terminal without grapheme clustering does. Bubble Tea v2 asks the terminal for mode 2027 at start; when a `tea.ModeReportMsg` for `ansi.ModeUnicodeCore` answers set, reset or permanently set, the terminal clusters graphemes, Bubble Tea turns the mode on, and the frame switches to `ansi.GraphemeWidth`. Under `WcWidth`, `Clean` removes each U+FE0F that follows a code point one cell wide, so `⚙️` draws as the one-cell text glyph that every terminal agrees on; under `GraphemeWidth` it returns the string as it stands (D5). No pane pads through Lip Gloss, which always measures by grapheme: a pane pads with `Measure` and applies a style to the padded text. `Wrap` fills each line with whole words split at single spaces and returns n lines; when words remain after line n, it drops words from that line until ` …` fits after them.

Measured in a trial outside the repository, with no terminal: `x/ansi` v0.11.8 gives 2 cells under both methods to each symbol of SYNTAX.md's gate sets and marks (❔ 📝 📌 🔧 ⚡ ⚓ 📐 🧱 📏 🔗 🌍 🚀 ⚪ 🟢 🟡 🔴 ✅ 🪫 ⛔ 👓 🤖 🧑 👀 🪆) and 1 to `—` `…` `×` `─` `▸` `▾` `·`. It gives `⚙️`, `🛠️` and `🖼️` 2 by grapheme and 1 by code point; Lip Gloss v1.1.0, which the prototype ran, and v2.0.6 both say 2. Every line of the twelve goldens measures its terminal width under both methods and under Lip Gloss v2. The prototype's own test shows the header one cell short when a terminal keeps `⚙️` narrow. Unverified, since no trial ran in a terminal emulator: that any emulator answers the mode query, that an emulator without the mode draws the stripped glyph in one cell, how an emulator set to draw ambiguous-width characters wide treats `—` and `─`, and symbols joined by U+200D.

### Colour and its absence

```go
// Styles holds every style a pane uses. The zero value draws plain text.
type Styles struct{ Title, Header, Parent, Muted, Cursor, Acts, Error lipgloss.Style }

func DefaultStyles() Styles
```

`Title`, `Header` and `Parent` are bold. `Muted`, for the status and help lines, is faint. `Cursor` is reverse: the id and task of the selected row, the header of the cursor column and the cell where they cross. `Acts` is bold in ANSI colour 3 and `Error` bold in ANSI colour 1. The program uses the terminal's 16 colours alone, so the terminal's theme decides light and dark, and it colours no symbol. No fact rests on colour: a parent has its `▾`, an acting cell its brackets, an error its `error:` prefix, and the status line names the cursor. Bubble Tea v2 detects the colour profile, honours `NO_COLOR`, and removes what the terminal cannot draw; the program adds no option.

### Settings

The choice persists in one file per viewer, `settings.json` in `tablotui/` under `os.UserConfigDir()`: `~/.config/tablotui/settings.json` on Linux. `--settings <file>` names another. Nothing goes into the repository.

```json
{
  "version": 1,
  "columns": {
    "function": "hide",
    "undefined": "show"
  }
}
```

A gate key maps to `hide` or `show`; a gate with no entry follows the window. The choices hold for every project the viewer opens (D4); a key that names no gate of the project in view stays in the file untouched. `settings.Save` writes sorted keys, two-space indent and a final newline to a temporary file in the same directory and renames it, with the directory at mode 0700 and the file at 0600. A missing file means no choice. A file that does not parse, or states another `version`, gives the notice `settings: <error>; this session keeps no column choice`, and the session then writes nothing, so a newer file survives.

### The command

```
tablotui [-C <dir>] [--settings <file>] [--fixture <dir>] [--version] [--help]
```

`-C` names the project directory, by default the current one. `--fixture` draws from files through `source.File`; without it this implementation exits 1 with `tablotui: this build has no tablo source; pass --fixture <dir>`, until the integrate gate adds the adapter. `--version` prints the banner the bootstrap prints. A long option with one hyphen exits 2 and names the two-hyphen form, as the prototype does. Exit 0 after a quit, 1 when the terminal program fails, 2 on a usage error. A load that fails never ends the program.

**Determinism.** `View` is a function of the model alone: no clock, no map order, no terminal query. The same fixture, size and keys give the same bytes.

**From the prototype.** The design keeps the tree walk, the scroll rule, widths taken over every row, the temporary-file write and the two-hyphen check. It drops the positional digits, the `⊘n` column, the file list on the command line with `w` cycling it, `--dump`, `--keys`, `--size`, `--chrome` and `--strip-vs16`.

## Conformance to the texts

The grid reproduces [VIEWS.md, Global tableau](https://github.com/nbyoung/tableaux/blob/main/VIEWS.md#global-tableau) in the layout of `docs/mockups/tableau.md`, and draws [Contextual tableau](https://github.com/nbyoung/tableaux/blob/main/VIEWS.md#contextual-tableau) data in the layout of `context.md` when f394 asks for it. The disclosure follows `tableau.html` and `context.html`.

| Level | In the mockups | In the grid |
|-------|----------------|-------------|
| glance | The root and its children; the fold count; `(31)` after a folded parent | The arrival of `GlanceStart`; `C` returns to it. Row: id, label, cells. Cell: the state and reason at the current gate, the marks after it, `—` where exempt, nothing where historical. |
| detail | Every row; the date and the note of each row; the folded counts gate by gate | `E`, or `enter` parent by parent, as the HTML unfolds branches. `d` opens the strip for the selected row, as the HTML opens a row's date. |
| provenance | The Git fact behind each cell, inside the note | `p` adds the facts of the cell under the cursor, which tablo sends at that level. |

- **Arrival by role.** `tableau.html` opens for the owner on the root and its children with every branch closed, and an observer sees the same: `GlanceStart`. `context.html` opens an assignee at detail with provenance closed, and a contributor on the person form with the parents of their tasks open: f394 supplies those starts.
- **The window** belongs to the two tableaux, and the grid is the only pane that draws one. It moves when the data moves: tablo recomputes it on every load. `w` and `W` change its width for the session; a session starts at the start's window.
- **Historical junctions.** A historical cell arrives empty and draws empty. `H` asks tablo for the marks, and `tableau-historical.json` shows the answer. The grid never fills a historical cell itself.
- **Divergence.** The Markdown mockups give the date and the note a column or a table of their own; a terminal has no width for them beside ten gates, so the strip shows them for one row at a time (D10).

## Decisions at review

1. **The Charm major.** v2, at `charm.land`: Bubble Tea v2.0.10, Lip Gloss v2.0.6, Bubbles v2.2.1, MIT. v2 reports the terminal's grapheme mode to the model, so the grid measures as the terminal draws; it takes the colour profile and the alternate screen out of global state, so a test fixes them; and the module proxy lists no v1 release after v1.3.10 while v2 stands at its tenth patch. Lip Gloss v1.1.0 also fails to build once another module raises `x/ansi` to v0.11.8, which the trial met. The cost: all five prototypes ran on v1, and v2 renames what they use (`View` returns `tea.View`, a key arrives as `tea.KeyPressMsg`), so their code ports and does not copy. The alternative keeps v1 as the README states, with no mode report: the grid then strips U+FE0F always.
2. **The fold count sits in the header**: `❔ ×0`, and `❔…📝 ×29` for a run, as `tableau.md` draws it. A header stays in view while rows scroll, and the count describes the column, not the first task. This binds tabloio's Status renderers `a3cc` and Text renderers `e0f7`, tableaud's Status templates `44bf`, tablo's `886d` and `f394` here. The alternative is `context.md`'s count in the first row under a header `🔗 … 🚀`.
3. **A hidden column folds.** A column the viewer hides joins the folded columns, with the same header and count, and the viewer may also show a column the window folds, as `tableau.html`'s control offers. The alternative is the prototype's one `⊘n` column for everything hidden.
4. **One settings file per viewer, for every project**, as JSON under the user's configuration directory, keyed by gate key. The alternative keeps a set per project, which needs an identity for a project that survives a second clone or a worktree.
5. **The symbol width.** Measure by grapheme when the terminal reports mode 2027; else measure by code point and remove U+FE0F after a narrow base. The alternative assumes every terminal widens the selector, as the prototype does by default. A recommendation in SYNTAX.md that a symbol be one code point of emoji presentation, as the gate sets now are, makes the question moot for most projects.
6. **A cell cursor.** `left` and `right` move the column cursor and `enter` folds the tree; `x`, `s` and `X` act at the cursor. The alternative is the prototype's: arrows fold the tree and digits toggle columns by position.
7. **The source.** The implementation draws from fixtures behind `source.Tableaux` and ships `--fixture`; the tablo adapter lands at this task's integrate gate, as a library call (A1). The alternative runs the `tablo` executable from the start, which fixes its command line before `4ed9` and `886d` design it.
8. **The number after a folded parent counts the rows beneath it**, every descendant, as `tableau.md` has `Method (31)`. `context.md` counts the children not drawn, `Method (4)`; the two mockups differ here as well. This binds the same designs as decision 2.
9. **The empty forms**, which VIEWS.md does not define: `loading…`, `no task in view` under the header, and `error: <message>`. The alternative leaves them to each front end; tabloio and tableaud meet the same gap.
10. **Detail in a strip.** The date, the note and the provenance show for the selected row beneath the grid, not as columns. The alternative adds a date column where the width allows, which makes the layout depend on the width in one more way.
